# Инструкция агенту: публикация Ai Transcriber на GitHub и в ReaPack

Публикуется только Ai Transcriber для Windows x64 из этого репозитория.
Публикация выполняется по отдельному прямому поручению Aiwist. Эта инструкция
сама по себе не разрешает отправлять файлы в интернет.

## 1. Состояние перед передачей

Подготовлен согласованный выпуск **1.0.2** для Windows x64. Рабочий репозиторий:

`D:\!Studio\Reaper\Scripts\Ai Transcriber`

GitHub: `https://github.com/Aiwist/ai-transcriber`, ветка `main`.

Установочный архив:

`D:\!Release\Ai_Transcriber_Setup_1.0.2_Windows.zip`

Рядом находится его `.sha256`. Устанавливаемая папка `Transcriber` в ZIP
побайтно совпадает с текущим комплектом ReaPack, включая инструкцию и манифесты.
В ZIP нет README для GitHub, скриншотов и этой инструкции разработчика.
CPU- и Vulkan-сборки сохранены без перекомпиляции; функции распознавания не менялись.

Готовый ZIP сохраняется в `D:\!Release`, прежние выпуски — в
`F:\Backup Scripts\Ai Transcriber`. Выпущенные архивы не перезаписываются.

Публикацию выполняет агент по отдельному поручению Aiwist.

## 2. Откуда брать файлы

### Исходники в GitHub

Отправляется Git-репозиторий:

`D:\!Studio\Reaper\Scripts\Ai Transcriber`

Использовать текущую проверенную ветку. Не создавать новый репозиторий
из распакованного ZIP и не откатывать последние правки README.

В Git должны остаться Lua, вспомогательные скрипты, лицензии, README,
`assets/screenshots`, индекс ReaPack и инструменты подготовки выпуска.

Файлы `.work`, `Transcriber/runtime`, EXE, SDK, модели, пользовательские данные
и архивы исключены через `.gitignore`. Не добавлять их принудительно в Git.

- `D:\!Studio\Reaper\Scripts\Ai Transcriber\README.md` — английский README.
- `D:\!Studio\Reaper\Scripts\Ai Transcriber\README.ru.md` — русский README.

README уже содержит относительные ссылки на изображения. Отдельными вложениями

сравнения с другими редакциями и инструкции публикации.

### Вложения GitHub Release для ReaPack

Для текущего номера 1.0.2 они подготовлены здесь:

`RELEASE_NOTES.md` в этой же папке — заготовка описания Release; её текст можно
использовать в описании, загружать этот файл как отдельное вложение необязательно.

Проверенные SHA-256 неизменённых EXE:


Обе сборки нужны. Не выбирать только одну и не переименовывать вложения:
индекс ReaPack содержит прямые ссылки на их имена.

### Вложения GitHub Release для обычной установки

Для выпуска 1.0.2 взять из `D:\!Release`:

- `Ai_Transcriber_Setup_<версия>_Windows.zip`;
- `Ai_Transcriber_Setup_<версия>_Windows.zip.sha256`.

В чистом ZIP должны быть BAT-установщик, вспомогательные файлы установки,
программа с обоими EXE, шрифты, лицензии и краткая инструкция `Установка.txt`.
ZIP-установщик сам устанавливает ReaImGui при необходимости. В способе ReaPack
ReaImGui выбирается отдельным пакетом.

GitHub автоматически добавит Source code ZIP/TAR. Это архивы исходников,
а не готовый установщик: EXE в них отсутствуют.

Архивы других продуктов в `D:\!Release` к этой публикации не относятся:
не загружать, не перепаковывать, не удалять и не перемещать их.

## 3. Проверки и финальная упаковка

Все команды подготовки запускаются из:

`D:\!Studio\Reaper\Scripts\Ai Transcriber`

```powershell
git status --short --branch
git log -5 --oneline
git remote -v
python tools/reapack.py check --require-runtime
```

Непосредственно перед внешними действиями проверить реальное состояние удалённого
репозитория, ветки, тегов и Releases через доступное подключение GitHub или Git.
Локальная отметка origin/main может быть устаревшей. Ошибка авторизации или
подключения не доказывает отсутствия репозитория, тега или Release.

При подготовке следующего выпуска сначала синхронизировать его номер:
`Transcriber/native_release.json`, основной Lua, проверку версии в
`Transcriber/setup/common.ps1`, установщик, инструкции и README. Перенести записи
из «Не выпущено» в CHANGELOG под согласованный номер и фактическую дату.
В `reapack.json` указать актуальные дату и описание. Не менять алгоритм движка.

Затем:

```powershell
python -m pip install -r tools/test-requirements.txt
python tools/reapack.py prepare
python tools/reapack.py check --require-runtime
python -m unittest discover -s tests -v
python tools/reapack.py stage-assets
python tools/package_release.py --output-dir 'D:\!Release'
```

Python нужен агенту для подготовки, а не конечному пользователю.
`prepare` согласует перечень файлов и контрольные суммы. `stage-assets` создаёт
папку `.work/reapack/v<версия>` с готовыми EXE и их суммами. `package_release.py`
не компилирует код и отказывается перезаписывать готовый ZIP.

Проверить новый ZIP: нет GitHub-README, `assets/screenshots`, `PUBLISHING.ru.md`,
Git, тестов, SDK и весов; оба EXE присутствуют. Все файлы устанавливаемой папки
`Transcriber` должны совпасть по именам и SHA-256 с текущим пакетом ReaPack.
В тестах есть отдельная проверка совпадения установки BAT и ReaPack.

Только после проверки нового выпуска предыдущий установочный ZIP этой же
редакции и его контрольную сумму перенести в `F:\Backup Scripts\Ai Transcriber`
без удаления или перезаписи существующих файлов и проверить хеши после переноса.
Архивы другого продукта не трогать. Это порядок из применимых AGENTS.md.

Все изменения исходников, документации и манифестов сохранить одним проверенным
Git-коммитом. Историю Git и авторов прежних коммитов без отдельного указания
не переписывать. В текущих авторских уведомлениях используется только Aiwist.

## 4. Порядок публикации после разрешения и успешных проверок

Подставлять согласованный окончательный номер. Для 1.0.2 тег называется
**`v1.0.2`**, для следующей версии соответственно **`v<версия>`**.

1. Зафиксировать проверенные исходники, индекс и манифесты. Записать полный SHA
   коммита. Не отправлять новый индекс в `main`, пока вложения недоступны.
2. Проверить отсутствие конфликтующего удалённого тега и Release. Если они уже
   существуют, изучить их содержимое; не перезаписывать и не применять force push.
3. Создать тег `v<версия>` на проверенном коммите и отправить только этот тег.
   Исходники по тегу должны в точности соответствовать проверенным манифестам.
4. Создать GitHub Release для этого тега и загрузить **пять вложений**:
   оба EXE, `SHA256SUMS.txt`, установочный ZIP и его `.sha256`.
   Использовать текст RELEASE_NOTES как основу описания. При новой нумерации
   явно выбрать Latest; существующие теги не удалять и не переименовывать.
5. Убедиться, что Release и вложения доступны публично, затем выполнить:

   ```powershell
   python tools/reapack.py verify-remote
   ```

   Эта команда читает все ссылки текущего пакета и сверяет SHA-256. При любой
   ошибке не открывать новый индекс пользователям. Отдельно скачать опубликованный
   ZIP и его сумму и сверить их с подготовленным локальным выпуском.
6. Только после успешной проверки опубликовать проверенный коммит в `main`.
   Если удалённая ветка успела измениться, сначала проверить изменения;
   не перетирать чужую работу принудительной отправкой.
7. Проверить результат GitHub Actions. Выполнить установку через ReaPack в
   отдельном профиле REAPER: действие появляется, ReaImGui проверяется, модель
   устанавливается, CPU и доступная видеокарта выбираются. Тестирование в рабочем
   музыкальном проекте и запуск новых тестовых ReaScript согласовывать отдельно.

Пользователям публикуется один адрес — общий индекс скриптов Aiwist:

```
https://raw.githubusercontent.com/Aiwist/ai-scripts/main/index.xml
```

Индекс проекта `index.xml` в этом репозитории — рабочий артефакт сборки:
из него собирается общий индекс (`python tools/build_index.py` в `Aiwist/ai-scripts`).
Отдельную ссылку на него не публиковать: пакет из двух индексов даёт конфликт
пути установки.

Не менять имя индекса **Aiwist**, категорию **Transcriber** и главное действие
**Aiwist_Transcriber.lua**. Они определяют путь:

`Scripts/Aiwist/Transcriber/Aiwist_Transcriber.lua`

Это сохраняет существующее действие и горячие клавиши.

- результат проверки всех ссылок, GitHub Actions и установки;
- любые оставшиеся ограничения проверки, без утверждений о непроведённых тестах.

Не обещать отсутствие антивирусных срабатываний. Чистый результат проверки
другого файла или другого выпуска этого не доказывает.
